La tabla bien tipada — ejemplo completo

sql 
CREATE TABLE alumnos (

  -- ID: siempre INT UNSIGNED AUTO_INCREMENT
  id               INT UNSIGNED    AUTO_INCREMENT PRIMARY KEY,

  -- Texto corto conocido → VARCHAR con límite razonable
  nombre           VARCHAR(100)   NOT NULL,
  email            VARCHAR(150)   NOT NULL UNIQUE,
  legajo           CHAR(8)       UNIQUE,

  -- Solo fecha (sin hora) → DATE
  fecha_nacimiento DATE,

  -- Número exacto con 2 decimales → DECIMAL
  promedio         DECIMAL(4,2),

  -- Verdadero/falso → BOOLEAN (internamente TINYINT(1))
  activo           BOOLEAN         DEFAULT TRUE,

  -- Estado de lista cerrada → ENUM
  estado           ENUM('cursando','egresado','baja') DEFAULT 'cursando',

  -- Fecha y hora automática → TIMESTAMP
  created_at       TIMESTAMP       DEFAULT CURRENT_TIMESTAMP,
  updated_at       TIMESTAMP       DEFAULT CURRENT_TIMESTAMP
                                    ON UPDATE CURRENT_TIMESTAMP
);
02 · Fechas y TIMESTAMP

Lo que más costó:
DATE vs TIMESTAMP

📌
La diferencia en una oración

DATE = solo la fecha, el usuario la ingresa (nacimiento, evento). TIMESTAMP = fecha + hora, MySQL la pone automáticamente (cuándo se creó/modificó un registro).

TipoGuardaSe llena soloCaso de uso típico
DATE2025-04-29NoFecha de nacimiento, fecha de un evento
TIME14:30:00NoHora de clase, horario de atención
DATETIME2025-04-29 14:30:00No (o sí con DEFAULT)Reservas, eventos con fecha y hora exacta
TIMESTAMP2025-04-29 14:30:00SÍ — con DEFAULT/ON UPDATEcreated_at, updated_at en CUALQUIER tabla

TIMESTAMP paso a paso — qué pasa en cada operación

sql · paso a paso 
-- PASO 1: Creamos la tabla con TIMESTAMP
CREATE TABLE posts (
  id         INT         AUTO_INCREMENT PRIMARY KEY,
  titulo     VARCHAR(200),
  created_at TIMESTAMP   DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP   DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- PASO 2: Insertamos UN registro
-- ⚠️ NO escribimos created_at ni updated_at — MySQL los completa solo
INSERT INTO posts (titulo) VALUES ('Mi primer post');

-- Resultado en la tabla:
-- id=1  titulo='Mi primer post'  created_at='2025-05-04 10:00:00'  updated_at='2025-05-04 10:00:00'

-- PASO 3: Modificamos el registro 2 horas después
UPDATE posts SET titulo = 'Título corregido' WHERE id = 1;

-- Resultado ahora:
-- created_at = '2025-05-04 10:00:00'  ← NO CAMBIÓ (cuándo se creó)
-- updated_at = '2025-05-04 12:00:00'  ← SÍ CAMBIÓ (cuándo se editó)

-- PASO 4: Consultar con formato legible
SELECT
  id,
  titulo,
  DATE_FORMAT(created_at, '%d/%m/%Y %H:%i') AS creado,
  DATE_FORMAT(updated_at, '%d/%m/%Y %H:%i') AS modificado,
  DATEDIFF(NOW(), created_at) AS dias_viejo
FROM posts;
⚠️
El error más común con fechas

Intentar poner WHERE fecha = NULL en vez de WHERE fecha IS NULL. Con fechas (y con cualquier campo), NULL se consulta con IS NULL o IS NOT NULL, nunca con =.

03 · CRUD

Las 4 operaciones
con una tabla de ejemplo

Usamos una sola tabla (alumnos) para ver el ciclo completo. Esta es exactamente la tabla que va a consultar la app móvil con fetch().

C — CREATE (INSERT)

sql 
-- Insertar uno
INSERT INTO alumnos (nombre, email, legajo, promedio)
VALUES ('Ana García', 'ana@tecni.edu', 'SW20001', 8.50);

-- Insertar varios a la vez (más eficiente)
INSERT INTO alumnos (nombre, email, legajo, promedio)
VALUES
  ('Carlos Ruiz',   'carlos@tecni.edu', 'SW20002', 7.20),
  ('Sofía Méndez',  'sofia@tecni.edu',  'SW20003', 9.10),
  ('Lucas Torres',  'lucas@tecni.edu',  'SW20004', 6.80);

-- ✅ id, activo, created_at, updated_at se completan solos

R — READ (SELECT)

sql 
-- Traer todos
SELECT * FROM alumnos;

-- Traer columnas específicas (mejor práctica)
SELECT id, nombre, email, promedio FROM alumnos;

-- Filtrar: solo activos con promedio mayor a 7
SELECT * FROM alumnos
WHERE activo = TRUE AND promedio > 7.00
ORDER BY promedio DESC
LIMIT 10;

-- Buscar por texto parcial
SELECT * FROM alumnos
WHERE nombre LIKE '%García%';  -- % = cualquier cosa

-- Contar cuántos hay
SELECT COUNT(*) AS total, AVG(promedio) AS promedio_general
FROM alumnos
WHERE activo = TRUE;

U — UPDATE ⚠️ siempre con WHERE

sql 
-- Actualizar un campo de un registro específico
UPDATE alumnos
SET promedio = 9.00, estado = 'egresado'
WHERE id = 1;
-- updated_at se actualiza SOLA gracias al ON UPDATE

-- ✅ Verificar SIEMPRE antes de ejecutar:
-- ¿Cuántos registros voy a afectar?
SELECT COUNT(*) FROM alumnos WHERE id = 1; -- debería ser 1

-- ⛔ SIN WHERE afecta TODOS los registros — nunca hacer esto
-- UPDATE alumnos SET activo = FALSE;  ← borra TODOS los activos

D — DELETE ⚠️ siempre con WHERE

sql 
-- Eliminar un registro específico
DELETE FROM alumnos WHERE id = 4;

-- ✅ Mejor práctica: soft delete (no borrar, desactivar)
UPDATE alumnos
SET activo = FALSE
WHERE id = 4;
-- El registro sigue existiendo, pero el sistema lo ignora
-- Así se puede recuperar si fue un error
04 · Relaciones y FK

Tablas que se
hablan entre sí

🔗
La regla del orden al crear tablas

Siempre crear primero la tabla padre (la que no tiene FK) y después la tabla hija (la que tiene FK). Si lo hacés al revés, MySQL da error porque no puede referenciar algo que no existe.

Relación 1:N — Un alumno tiene muchos proyectos

sql · 1:N 
-- 1️⃣ PRIMERO: tabla padre (alumnos ya existe de antes)

-- 2️⃣ DESPUÉS: tabla hija con la FK
CREATE TABLE proyectos (
  id           INT UNSIGNED    AUTO_INCREMENT PRIMARY KEY,

  -- La FK: apunta al id de la tabla alumnos
  alumno_id    INT UNSIGNED    NOT NULL,

  nombre       VARCHAR(200)   NOT NULL,
  tecnologia   ENUM('React Native','React Web','PHP','Otro'),
  nota         DECIMAL(4,2),
  created_at   TIMESTAMP       DEFAULT CURRENT_TIMESTAMP,

  -- Declarar la FOREIGN KEY
  FOREIGN KEY (alumno_id)
    REFERENCES alumnos(id)
    ON DELETE CASCADE   -- si se borra el alumno, sus proyectos también
    ON UPDATE CASCADE   -- si cambia el id del alumno, se actualiza acá
);

-- Insertar respetando la FK
INSERT INTO proyectos (alumno_id, nombre, tecnologia, nota)
VALUES (1, 'App de Recordatorios', 'React Native', 9.50);
-- ✅ alumno_id=1 existe en la tabla alumnos → funciona
-- ❌ alumno_id=999 no existe → ERROR de FK

-- JOIN para ver proyectos CON el nombre del alumno
SELECT
  p.nombre     AS proyecto,
  p.nota,
  p.tecnologia,
  a.nombre     AS alumno,
  a.legajo
FROM       proyectos p
INNER JOIN alumnos   a ON p.alumno_id = a.id
ORDER BY p.nota DESC;

Opción¿Qué hace?Cuándo usarlo

05 · Errores comunes

Los errores que
siempre aparecen

Estos son los errores que más se repiten. Reconocerlos ahorra mucho tiempo.

ERROR 1452 · FK fails
Intentar insertar con un FK que no existe en la tabla padre.
✅ Verificar que el ID padre exista antes de hacer el INSERT hijo.
ERROR 1451 · Cannot delete parent
Intentar borrar un registro padre que tiene hijos referenciándolo (ON DELETE RESTRICT).
✅ Borrar primero los hijos, o cambiar a ON DELETE CASCADE.
ERROR 1062 · Duplicate entry
Insertar un valor repetido en una columna UNIQUE (email, legajo).
✅ Verificar con SELECT antes del INSERT, o usar INSERT IGNORE.
UPDATE sin WHERE
Se modifica TODA la tabla. No da error, simplemente destruye los datos.
✅ SIEMPRE poner WHERE id = n. Probar el SELECT antes del UPDATE.
WHERE campo = NULL
NULL no se compara con =. La consulta devuelve 0 resultados aunque haya NULLs.
✅ Usar siempre IS NULL o IS NOT NULL.
FK antes que la tabla padre
Crear la tabla hija (con FK) antes que la tabla padre. MySQL no puede referenciar algo que no existe.
✅ Crear siempre primero la tabla padre, después la hija.
06 · Quiz de verificación

¿Quedó claro?
Tocá para ver la respuesta

Tocá cada tarjeta para revelar la respuesta. Primero intentá responder mentalmente.

Pregunta 01
¿Qué tipo de dato uso para guardar el precio de un producto?
DECIMAL(10,2)

Nunca FLOAT ni DOUBLE para dinero — tienen errores de redondeo. DECIMAL es exacto.
👆 Tocá para ver
Pregunta 02
¿Qué hace ON UPDATE CURRENT_TIMESTAMP en un campo TIMESTAMP?
Actualiza automáticamente el campo a la fecha y hora actual cada vez que se hace un UPDATE en esa fila. No hay que escribirlo en la query.
👆 Tocá para ver
Pregunta 03
¿Por qué no se puede crear la tabla hija antes que la tabla padre cuando hay FK?
Porque la FK referencia a una columna de la tabla padre. Si la tabla padre no existe todavía, MySQL no puede crear la referencia → ERROR 1215.
👆 Tocá para ver
Pregunta 04
¿Cuál es la diferencia entre DATE y TIMESTAMP?
DATE guarda solo la fecha (YYYY-MM-DD), sin hora. TIMESTAMP guarda fecha + hora y puede completarse automáticamente con DEFAULT CURRENT_TIMESTAMP.
👆 Tocá para ver
Pregunta 05
¿Qué pasa si hago UPDATE sin WHERE?
Se actualiza TODA la tabla. MySQL no da error, simplemente cambia todos los registros. Es uno de los errores más graves y no tiene deshacer fácil.
👆 Tocá para ver
Pregunta 06
¿Qué es ON DELETE CASCADE?
Cuando se borra un registro padre, MySQL borra automáticamente todos los registros hijos que lo referencian. Ej: borrar un usuario borra sus publicaciones.
👆 Tocá para ver
Pregunta 07
¿Cómo busco registros donde un campo es NULL?
SELECT * FROM tabla WHERE campo IS NULL;

Nunca con = NULL. El operador = no funciona con NULL en SQL.
👆 Tocá para ver
Pregunta 08
¿Para qué sirve el INNER JOIN?
Para combinar filas de dos tablas según una condición. Devuelve solo las filas que tienen match en AMBAS tablas. Ej: ver proyectos con el nombre del alumno dueño.
