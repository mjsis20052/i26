01 · Fundamentos

Tipos de datos en MySQL

Cuando creamos una tabla, cada columna necesita un tipo. El tipo le dice a MySQL qué clase de dato puede guardar ahí y cuánto espacio reservar. Elegir mal el tipo puede hacer que la base de datos sea lenta, desperdicie espacio o guarde datos incorrectos.

💡
¿Por qué importa el tipo?

Si guardamos la edad en un campo VARCHAR en vez de INT, MySQL no puede hacer operaciones como "encontrar a todos los mayores de 18". Los datos son correctos visualmente, pero no funcionan como números.

Tipos numéricos

TipoEjemplo de valorRangoCuándo usarlo
INT42, -10, 0-2.1B a 2.1BIDs, edades, cantidades enteras
INT UNSIGNED0, 1, 5000 a 4.2BIDs que nunca son negativos (más común para PK)
TINYINT0, 1, 127-128 a 127Flags booleanos (0/1), estados simples
DECIMAL(10,2)1234.56ExactoPrecios, dinero (nunca FLOAT para plata)
FLOAT / DOUBLE3.14159AproximadoCoordenadas, mediciones científicas
BIGINT9999999999Muy grandeIDs de redes sociales, contadores muy grandes

Tipos de texto

TipoEjemploMáximoCuándo usarlo
VARCHAR(n)'Ana García'65,535 charsNombres, emails, títulos. El n es el máximo de chars
CHAR(n)'AR', 'USD'255 charsTextos de largo fijo: códigos de país, DNI
TEXT'Descripción larga...'65,535 charsDescripciones, comentarios, posts
MEDIUMTEXTArtículo entero16 MBContenido HTML, artículos largos
LONGTEXTLibro entero4 GBLogs, datos muy extensos
ENUM'activo','inactivo'65,535 opcionesEstados con valores fijos y conocidos
✅
Regla de oro: VARCHAR vs TEXT

Si el texto va a tener un límite conocido (nombre, email, título), usá VARCHAR(200). Si es contenido largo sin límite claro (descripción, comentario), usá TEXT. No uses TEXT para todo: es más lento en búsquedas.

Tipos booleanos

MySQL no tiene un tipo BOOLEAN verdadero. Internamente usa TINYINT(1): el valor 0 significa falso y el 1 verdadero.

sql 
-- Estas dos formas son equivalentes en MySQL:
CREATE TABLE usuarios (
  activo   BOOLEAN,           -- MySQL lo convierte a TINYINT(1)
  verificado TINYINT(1) DEFAULT 0  -- 0=false, 1=true
);

-- Para insertar:
INSERT INTO usuarios (activo) VALUES (TRUE);   -- o VALUES(1)
INSERT INTO usuarios (activo) VALUES (FALSE);  -- o VALUES(0)

-- Para consultar:
SELECT * FROM usuarios WHERE activo = 1;     -- los activos
SELECT * FROM usuarios WHERE activo = 0;     -- los inactivos
02 · Lo que se complicó hoy

Tipos de fecha y hora

Este es el tema que más confusión generó hoy. Vamos a verlo despacio con ejemplos concretos.

Los 5 tipos de fecha en MySQL

TipoQué guardaFormatoEjemplo real
DATESolo fecha, sin horaYYYY-MM-DD'2025-04-29'
TIMESolo hora, sin fechaHH:MM:SS'14:30:00'
DATETIMEFecha + hora. No cambia solaYYYY-MM-DD HH:MM:SS'2025-04-29 14:30:00'
TIMESTAMPFecha + hora. Puede actualizarse automáticamenteYYYY-MM-DD HH:MM:SS'2025-04-29 14:30:00'

¿Qué es TIMESTAMP exactamente?

Un TIMESTAMP guarda un momento exacto en el tiempo (fecha + hora + zona horaria). La magia es que MySQL puede llenarlo automáticamente cuando se inserta un registro y actualizarlo cuando se modifica.

sql · timestamp en práctica 
CREATE TABLE publicaciones (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  titulo      VARCHAR(200) NOT NULL,

  -- created_at: se llena SOLA cuando hacés el INSERT
  -- DEFAULT CURRENT_TIMESTAMP = "poner la hora actual cuando se crea"
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

  -- updated_at: se actualiza SOLA cada vez que hacés UPDATE
  -- ON UPDATE CURRENT_TIMESTAMP = "poner la hora actual cuando se modifica"
  updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- Si hacemos esto:
INSERT INTO publicaciones (titulo) VALUES ('Mi primera publicación');

-- MySQL guarda AUTOMÁTICAMENTE (sin que nosotros lo escribamos):
-- created_at  = '2025-04-29 14:30:00'  ← momento del INSERT
-- updated_at  = '2025-04-29 14:30:00'  ← mismo momento

-- Si después actualizamos:
UPDATE publicaciones SET titulo = 'Título corregido' WHERE id = 1;

-- Ahora:
-- created_at  = '2025-04-29 14:30:00'  ← NO cambió (cuándo se creó)
-- updated_at  = '2025-04-29 15:45:22'  ← SÍ cambió (cuándo se editó)
⚠️
TIMESTAMP vs DATETIME ¿cuál usar?

TIMESTAMP: perfecto para created_at y updated_at. Se actualiza solo. Rango: 1970–2038.
DATETIME: para fechas que el usuario ingresa (fecha de nacimiento, fecha de un evento). Rango: 1000–9999. No tiene el límite del 2038.

Funciones de fecha más usadas

sql · funciones de fecha 
-- Obtener la fecha/hora actual
SELECT NOW();              -- '2025-04-29 14:30:00'  (fecha + hora)
SELECT CURDATE();          -- '2025-04-29'           (solo fecha)
SELECT CURTIME();          -- '14:30:00'             (solo hora)

-- Extraer partes de una fecha
SELECT YEAR(created_at)    FROM publicaciones;   -- → 2025
SELECT MONTH(created_at)   FROM publicaciones;   -- → 4
SELECT DAY(created_at)     FROM publicaciones;   -- → 29

-- Formatear fecha para mostrar
SELECT DATE_FORMAT(created_at, '%d/%m/%Y') FROM publicaciones;
-- → '29/04/2025'

SELECT DATE_FORMAT(created_at, '%d de %M de %Y') FROM publicaciones;
-- → '29 de April de 2025'

-- Filtrar por fecha
SELECT * FROM publicaciones
WHERE created_at >= '2025-01-01'
  AND created_at <  '2025-05-01';   -- publicaciones de enero a abril

-- Calcular diferencia entre fechas
SELECT DATEDIFF(NOW(), created_at) AS dias_desde_creacion
FROM publicaciones;

NULL — el valor que no es ningún valor

Un campo NULL significa que el dato no existe o se desconoce. Es diferente a cero o a una cadena vacía. Hay que manejarlo con cuidado.

sql · null 
-- Campo que puede ser NULL (no es obligatorio)
CREATE TABLE usuarios (
  telefono  VARCHAR(20)             -- puede ser NULL (opcional)
  email     VARCHAR(150) NOT NULL  -- NO puede ser NULL (obligatorio)
);

-- Buscar registros donde el campo ES null
SELECT * FROM usuarios WHERE telefono IS NULL;

-- Buscar registros donde el campo NO ES null
SELECT * FROM usuarios WHERE telefono IS NOT NULL;

-- ⚠️ ESTE ERROR ES MUY COMÚN: no funciona con = ni !=
SELECT * FROM usuarios WHERE telefono = NULL;    -- ❌ no devuelve nada
SELECT * FROM usuarios WHERE telefono != NULL;   -- ❌ tampoco funciona
03 · CRUD completo

Las 4 operaciones: CRUD

CRUD es el acrónimo de las 4 operaciones fundamentales que se hacen con datos. Todo sistema, de cualquier tipo, se reduce a estas 4 operaciones.

C
Create
INSERT INTO
R
Read
SELECT
U

D

Vamos a trabajar con una sola tabla de ejemplo para entender las 4 operaciones antes de pasar a las relaciones:

sql · crear la tabla 
CREATE TABLE alumnos (
  id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  nombre     VARCHAR(100) NOT NULL,
  email      VARCHAR(150) UNIQUE NOT NULL,
  legajo     CHAR(8) UNIQUE,
  promedio   DECIMAL(4,2),
  activo     TINYINT(1) DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

C — CREATE (INSERT INTO)

sql · insert 
-- Insertar un registro (especificando columnas — recomendado)
INSERT INTO alumnos (nombre, email, legajo, promedio)
VALUES ('Ana García', 'ana@tecni.edu', 'SW20001', 8.50);

-- Insertar múltiples registros de una sola vez
INSERT INTO alumnos (nombre, email, legajo, promedio)
VALUES
  ('Carlos Ruiz',    'carlos@tecni.edu', 'SW20002', 7.20),
  ('Sofía Méndez',   'sofia@tecni.edu',  'SW20003', 9.10),
  ('Lucas Herrera',  'lucas@tecni.edu',  'SW20004', 6.80);

-- El id y created_at se llenan SOLOS (AUTO_INCREMENT y DEFAULT)

R — READ (SELECT)

sql · select 
-- Traer todos los registros, todas las columnas
SELECT * FROM alumnos;

-- Traer solo algunas columnas
SELECT id, nombre, email FROM alumnos;

-- Filtrar con WHERE
SELECT * FROM alumnos WHERE promedio >= 8;
SELECT * FROM alumnos WHERE activo = 1;
SELECT * FROM alumnos WHERE nombre LIKE '%García%';  -- contiene "García"

-- Ordenar resultados
SELECT * FROM alumnos ORDER BY promedio DESC;    -- mayor a menor
SELECT * FROM alumnos ORDER BY nombre ASC;      -- A a Z

-- Limitar cantidad de resultados
SELECT * FROM alumnos LIMIT 10;                  -- solo los primeros 10
SELECT * FROM alumnos LIMIT 10 OFFSET 20;        -- del 21 al 30 (paginación)

-- Contar, promediar, sumar
SELECT COUNT(*) AS total       FROM alumnos;
SELECT AVG(promedio) AS media  FROM alumnos;
SELECT MAX(promedio) AS mejor  FROM alumnos;
SELECT MIN(promedio) AS peor   FROM alumnos;

U — UPDATE

sql · update 
-- Actualizar un campo de un registro específico
UPDATE alumnos
SET promedio = 9.20
WHERE id = 1;

-- Actualizar múltiples campos a la vez
UPDATE alumnos
SET promedio = 8.50, activo = 0
WHERE id = 3;

-- Actualizar TODOS los registros que cumplen una condición
UPDATE alumnos
SET activo = 0
WHERE promedio < 4;

-- ⚠️ PELIGRO: UPDATE sin WHERE actualiza TODA la tabla
UPDATE alumnos SET activo = 0;  -- ← desactiva a TODOS
🚨
El error más común: UPDATE y DELETE sin WHERE

Un UPDATE o DELETE sin WHERE afecta todos los registros de la tabla. Antes de ejecutar uno, siempre hacé un SELECT con la misma condición para verificar qué registros vas a modificar.

D — DELETE

sql · delete 
-- Eliminar un registro específico
DELETE FROM alumnos WHERE id = 4;

-- Eliminar varios registros
DELETE FROM alumnos WHERE activo = 0;

-- ✅ BUENA PRÁCTICA: primero verificá con SELECT qué vas a borrar
SELECT * FROM alumnos WHERE activo = 0;  -- ← primero esto
DELETE FROM alumnos WHERE activo = 0;   -- ← después esto

-- Vaciar tabla COMPLETA (cuidado)
TRUNCATE TABLE alumnos;   -- borra todo y resetea el auto_increment

-- ⚠️ PELIGRO: sin WHERE borra todo
DELETE FROM alumnos;   -- ← elimina TODOS los alumnos
04 · Relaciones

Relaciones entre tablas

En el mundo real, los datos se relacionan entre sí. Un alumno cursa muchas materias. Un producto pertenece a una categoría. Un pedido tiene muchos productos. Las bases de datos relacionales están diseñadas exactamente para esto.

Los 3 tipos de relación

TipoDescripciónEjemploCómo se implementa
1 a 1
1:1		 Un registro se relaciona con exactamente un registro de otra tabla Usuario → Perfil extendido FK con UNIQUE en la tabla secundaria
1 a muchos
1:N		 Un registro se relaciona con muchos de otra tabla Categoría → muchos Productos
Alumno → muchas Notas		 FK en la tabla del lado "muchos"
Muchos a muchos
N:M		 Muchos registros de A se relacionan con muchos de B Alumnos ↔ Materias
Pedidos ↔ Productos		 Tabla intermedia (pivot) con dos FK

05 · Lo que más se complicó

Claves foráneas: FOREIGN KEY

Una clave foránea (FK) es una columna que apunta al ID de otra tabla. Es lo que crea la relación real entre dos tablas y hace que MySQL garantice que los datos sean coherentes.

🔗
¿Para qué sirve la FK?

Sin FK podría existir una nota con alumno_id = 999 y ningún alumno con ese ID. La FK le dice a MySQL: "no permitas guardar una nota si el alumno_id no existe en la tabla alumnos". Eso se llama integridad referencial.

Crear las tablas con FK paso a paso

sql · tabla alumnos (primero) 
-- ⚠️ ORDEN IMPORTANTE: primero crear las tablas "padre"
-- La tabla que tiene la PK siempre va primero

CREATE TABLE alumnos (
  id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  nombre     VARCHAR(100) NOT NULL,
  email      VARCHAR(150) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE materias (
  id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  nombre     VARCHAR(100) NOT NULL,
  codigo     CHAR(6) UNIQUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
sql · tabla notas (después, con FK) 
-- Después creamos la tabla "hija" que tiene las FK
CREATE TABLE notas (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  -- Estas columnas van a guardar IDs de otras tablas
  alumno_id   INT UNSIGNED NOT NULL,
  materia_id  INT UNSIGNED NOT NULL,

  nota        DECIMAL(4,2) NOT NULL,
  fecha_examen DATE,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

  -- Aquí declaramos las FOREIGN KEYS
  -- FOREIGN KEY (columna_local) REFERENCES tabla_padre(columna_pk)
  FOREIGN KEY (alumno_id)  REFERENCES alumnos(id)  ON DELETE CASCADE,
  FOREIGN KEY (materia_id) REFERENCES materias(id) ON DELETE RESTRICT
);

ON DELETE — ¿Qué pasa cuando borro el padre?

Si borro un alumno, ¿qué pasa con sus notas? MySQL necesita saberlo. Se define con ON DELETE:

Opción¿Qué hace?Cuándo usarlo
CASCADEBorra también los registros hijos automáticamenteNotas de un alumno, comentarios de un post
RESTRICTImpide borrar el padre si tiene hijos (error)No borrar una materia si tiene notas registradas
SET NULLPone NULL en la FK del hijoSi el padre es opcional
NO ACTIONIgual que RESTRICT (default)Cuando querés control manual

Insertar datos relacionados

sql · insertar con fk 
-- 1. Primero insertar los padres
INSERT INTO alumnos (nombre, email) VALUES
  ('Ana García',   'ana@tecni.edu'),
  ('Carlos Ruiz',  'carlos@tecni.edu');
-- Ana quedó con id=1, Carlos con id=2

INSERT INTO materias (nombre, codigo) VALUES
  ('Base de Datos',  'BD001'),
  ('Programación',   'PR001');
-- Base de Datos id=1, Programación id=2

-- 2. Después insertar los hijos con los IDs correctos
INSERT INTO notas (alumno_id, materia_id, nota, fecha_examen) VALUES
  (1, 1, 8.50, '2025-04-15'),  -- Ana en Base de Datos: 8.5
  (1, 2, 9.20, '2025-04-20'),  -- Ana en Programación: 9.2
  (2, 1, 7.00, '2025-04-15');  -- Carlos en Base de Datos: 7.0

-- ⚠️ Esto fallaría porque no existe alumno_id=999:
INSERT INTO notas (alumno_id, materia_id, nota) VALUES (999, 1, 8.0);
-- ERROR 1452: Cannot add or update a child row: a foreign key constraint fails

JOIN — Consultar tablas relacionadas juntas

Para traer datos de varias tablas en una sola consulta, usamos JOIN. Es la operación más poderosa de SQL.

sql · inner join 
-- INNER JOIN: trae solo los registros que tienen coincidencia en ambas tablas

SELECT
  a.nombre     AS alumno,
  m.nombre     AS materia,
  n.nota,
  n.fecha_examen
FROM notas n
  INNER JOIN alumnos  a ON n.alumno_id  = a.id
  INNER JOIN materias m ON n.materia_id = m.id
ORDER BY a.nombre, m.nombre;

-- Resultado:
-- alumno       | materia         | nota | fecha_examen
-- -------------|-----------------|------|-------------
-- Ana García   | Base de Datos   | 8.50 | 2025-04-15
-- Ana García   | Programación    | 9.20 | 2025-04-20
-- Carlos Ruiz  | Base de Datos   | 7.00 | 2025-04-15

-- Filtrar: notas de un alumno específico
SELECT m.nombre AS materia, n.nota
FROM notas n
  INNER JOIN materias m ON n.materia_id = m.id
WHERE n.alumno_id = 1;   -- solo notas de Ana (id=1)

-- Promedio de cada alumno
SELECT
  a.nombre,
  AVG(n.nota) AS promedio,
  COUNT(n.id) AS materias_rendidas
FROM notas n
  INNER JOIN alumnos a ON n.alumno_id = a.id
GROUP BY a.id, a.nombre
ORDER BY promedio DESC;
✅
Truco para recordar JOIN

Pensá en el JOIN como un "pegamento" entre tablas. FROM notas n INNER JOIN alumnos a ON n.alumno_id = a.id dice: "traé las notas, y pegalas con los alumnos donde el alumno_id de la nota coincida con el id del alumno".

Tipos de JOIN (visual)

JOIN¿Qué devuelve?Cuándo usarlo
INNER JOINSolo los que tienen coincidencia en AMBAS tablasLa mayoría de los casos (el más común)
LEFT JOINTodos de la izquierda + coincidencias de la derecha (NULL si no hay)Alumnos aunque no tengan notas aún
RIGHT JOINTodos de la derecha + coincidencias de la izquierdaPoco común, se puede reescribir como LEFT
sql · left join 
-- LEFT JOIN: muestra TODOS los alumnos, incluso los que no rindieron nada
SELECT
  a.nombre,
  IFNULL(COUNT(n.id), 0) AS examenes_rendidos
FROM alumnos a
  LEFT JOIN notas n ON n.alumno_id = a.id
GROUP BY a.id, a.nombre;

-- Resultado incluye alumnos con 0 exámenes (INNER JOIN los excluiría)

CRUD Avanzado: El "Click" de las Relaciones

Sabemos que les costó entender cómo se conectan las tablas en un sistema real. Aquí está el resumen definitivo para que no queden dudas:

1. Actualización de Fechas (Lo que siempre preguntan)

¿Cómo actualizo una fecha de examen o de entrega sin romper nada?

sql · update de fecha 
-- Cambiar la fecha de un examen específico
UPDATE notas 
SET fecha_examen = '2025-05-10', nota = 9.50
WHERE alumno_id = 1 AND materia_id = 2;

2. El Secreto de las FK (Foreign Keys)

La FK no es solo un número; es un vínculo de integridad. Si intentás borrar un alumno que tiene notas y la FK está en RESTRICT, MySQL te va a frenar. Eso es seguridad.

🧠
¿Cuándo hace "click"?

Hace click cuando entendés que la base de datos es la verdad del sistema. PHP y React Native solo muestran esa verdad. Si la base de datos está bien relacionada con sus FKs y tipos de datos correctos, el resto del código fluye solo.

08 · El Próximo Paso

🏁 Hacia el Proyecto Final

Ya dominás las piezas sueltas (CRUD, FK, Relaciones). El verdadero poder aparece cuando integrás esto en una aplicación real. Tu camino a seguir es:

1. El Mapa de Datos

Diseñá tu propio DER (Diagrama Entidad Relación). No programes ni una línea hasta que tus tablas y FKs tengan sentido en papel o en dbdiagram.io.

2. El Motor MySQL

Creá la base de datos en XAMPP. Insertá datos de prueba reales. Hacé los JOINs a mano en la consola SQL antes de pasarlos a tu código PHP o Node.js.

3. La Interfaz Viva

Conectá tu Front-end (React Native o Web) con esta base de datos. Recordá: el usuario nunca ve el SQL, solo ve la experiencia que vos construiste sobre él.

🚀
Reto Semanal:

Tomá tu idea de proyecto y definí las 3 tablas principales. Asegurate de que al menos dos estén relacionadas con una FOREIGN KEY. Si lográs que un DELETE CASCADE funcione correctamente, ya estás en el siguiente nivel.
