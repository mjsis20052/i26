01 — Introducción

El stack moderno que usa el mercado

Antes de escribir una línea de código, necesitamos entender qué es cada herramienta, para qué sirve y por qué el mercado las usa juntas. Esto es lo mismo que aprender los nombres de las herramientas de un carpintero antes de construir un mueble.

¿Cómo evolucionó el frontend?

Durante muchos años, el servidor generaba el HTML completo y lo mandaba al navegador. Eso se llama SSR clásico (Server Side Rendering). Después llegó jQuery y JavaScript empezó a modificar la página sin recargarla. Luego vinieron React, Vue y Angular, que llevaron todo el renderizado al navegador (CSR - Client Side Rendering). El problema: la página tardaba en cargar porque el navegador tenía que descargar mucho JavaScript antes de mostrar algo.

Next.js resuelve eso combinando los dos mundos: pre-renderiza en el servidor y luego "hidrata" en el cliente. Hoy con el App Router y los React Server Components, podés elegir componente por componente si corre en el servidor o en el cliente.

🏠
SSR
El servidor genera el HTML completo. Rápido para el usuario. El servidor hace todo el trabajo.
⚛️
CSR
El navegador genera el HTML con JavaScript. Interactivo, pero carga lenta la primera vez.
▲
Next.js
Lo mejor de los dos mundos. Pre-renderiza en el servidor, hidrata en el cliente. Full Stack en un proyecto.
🧩
Server Components
Componentes que corren solo en el servidor. Acceden a la base de datos directamente, sin API. Magia.

02 — Herramientas

npm vs npx vs Git vs Git Bash

En la clase de hoy usamos varias herramientas desde la consola. Es fundamental entender qué hace cada una, porque son diferentes y se confunden fácilmente.

npm — El gestor de paquetes

npm significa Node Package Manager. Es la herramienta que instala y gestiona las librerías (paquetes) que usa tu proyecto. Viene instalado automáticamente con Node.js.

Pensalo como el almacén de materiales de construcción. Cuando necesitás ladrillos (React) o cemento (Tailwind), le pedís al almacén que te los traiga.

bashterminal
$ npm install framer-motion       # instala una librería en tu proyecto
$ npm install prisma @prisma/client # instala dos librerías juntas
$ npm run dev                       # ejecuta un script definido en package.json
$ npm run build                     # construye el proyecto para producción

npx — El ejecutor de paquetes

npx ejecuta un paquete sin necesidad de instalarlo permanentemente. Lo descarga, lo corre y lo descarta. Es perfecto para herramientas que usás una vez para crear o configurar algo.

Siguiendo la metáfora: si npm es el almacén, npx es el servicio de alquiler. Lo usás para la tarea, lo devolvés.

bashterminal
$ npx create-next-app@latest reservas # crea un proyecto nuevo (lo ejecuta sin instalar)
$ npx prisma init                      # inicializa Prisma en el proyecto
$ npx prisma migrate dev               # crea las tablas en la base de datos
$ npx shadcn@latest init               # configura shadcn/ui

Git — El control de versiones

Git es el sistema que guarda el historial de cambios de tu código. Con Git podés volver atrás en el tiempo, trabajar en equipo sin pisarse, y subir tu código a plataformas como GitHub.

Es como el control de cambios de Word, pero profesional y para código. Cada vez que hacés un commit, guardás una "foto" del estado del proyecto en ese momento.

bashcomandos git básicos
$ git init                  # inicia un repositorio en la carpeta actual
$ git add .                 # marca todos los archivos para guardar
$ git commit -m "primer commit"  # guarda la foto con un mensaje
$ git push origin main      # sube los cambios a GitHub
$ git clone [url]           # descarga un proyecto de GitHub

Git Bash — La pregunta de la clase

Un alumno preguntó: "¿Cuál es la diferencia entre Git y Git Bash?" Muy buena pregunta. Son cosas distintas:

🔧
Git
El programa que gestiona el historial de versiones. La herramienta en sí. Corre detrás de escena.
🖥️
Git Bash
Una terminal (consola) para Windows que simula el entorno Linux/Mac. Te permite usar Git y comandos Unix desde Windows.
💡
La analogía perfecta
Git es el motor. Git Bash es el panel de control desde donde manejás ese motor en Windows. En Mac y Linux no necesitás Git Bash porque ya tienen una terminal Unix nativa (la Terminal o iTerm).
✨
Tip profesional
La terminal integrada de VSCode (Ctrl+J) funciona perfectamente para todo. No necesitás abrir Git Bash por separado si usás VSCode.

¿Qué es TypeScript?
JavaScript normal te deja hacer let edad = "veinte" cuando debería ser un número. TypeScript lo detecta y te avisa antes de ejecutar. Es como tener un corrector automático pero para lógica de código. Hoy es el estándar en cualquier empresa de software.

¿Qué es el App Router?

El App Router es el sistema de rutas nuevo de Next.js (desde la versión 13). Cada carpeta dentro de app/ se convierte automáticamente en una URL. Además introduce los React Server Components: componentes que corren solo en el servidor y pueden acceder a la base de datos directamente.

07 — Backend

Base de datos con Prisma ORM

Prisma es el puente entre tu código TypeScript y la base de datos. En vez de escribir SQL crudo, escribís objetos TypeScript y Prisma los traduce. Además detecta errores de tipos antes de ejecutar.

¿Qué es un ORM?

ORM significa Object-Relational Mapper. Traduce tablas de la base de datos en objetos de código. Sin ORM escribís: SELECT * FROM reservas WHERE fecha = '2026-05-27'. Con Prisma escribís: prisma.reserva.findMany({"{"} where: {"{"} fecha {"}"} {"}"} ). Más legible, más seguro, con autocompletado.

El schema.prisma — el corazón de la base de datos

prismaprisma/schema.prisma
// Motor de base de datos (SQLite para desarrollo, PostgreSQL para producción)
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

// MODELO: Mesa del restaurante
model Mesa {
  id        Int       @id @default(autoincrement())
  numero    Int       @unique
  capacidad Int
  reservas  Reserva[]
  createdAt DateTime  @default(now())
}

// MODELO: Cliente
model Cliente {
  id       Int       @id @default(autoincrement())
  nombre   String
  email    String    @unique
  telefono String?   // ? = campo opcional
  reservas Reserva[]
}

// MODELO: Reserva (el núcleo del MVP)
model Reserva {
  id        Int          @id @default(autoincrement())
  fecha     DateTime
  horario   String       // "12:00", "13:30", "20:00"
  personas  Int
  estado    EstadoReserva @default(PENDIENTE)
  notas     String?
  
  // Relaciones
  mesaId    Int
  mesa      Mesa     @relation(fields: [mesaId], references: [id])
  clienteId Int
  cliente   Cliente  @relation(fields: [clienteId], references: [id])
  
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

// ENUM: estados posibles de una reserva
enum EstadoReserva {
  PENDIENTE
  CONFIRMADA
  CANCELADA
  COMPLETADA
}

08 — API

API REST con route.ts

En Next.js con App Router, las APIs se crean con archivos route.ts dentro de la carpeta app/api/. Cada archivo exporta funciones con el nombre del método HTTP que maneja.

typescriptsrc/app/api/reservas/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { prisma } from '@/lib/prisma'

// GET /api/reservas — trae todas las reservas
export async function GET() {
  try {
    const reservas = await prisma.reserva.findMany({
      include: {
        cliente: true,    // incluye los datos del cliente
        mesa: true,       // incluye los datos de la mesa
      },
      orderBy: { fecha: 'asc' }
    })
    return NextResponse.json(reservas)
  } catch (error) {
    return NextResponse.json(
      { error: 'Error al obtener reservas' },
      { status: 500 }
    )
  }
}

// POST /api/reservas — crea una nueva reserva
export async function POST(request: NextRequest) {
  try {
    const body = await request.json()
    
    const reserva = await prisma.reserva.create({
      data: {
        fecha:    new Date(body.fecha),
        horario:  body.horario,
        personas: body.personas,
        mesaId:   body.mesaId,
        clienteId: body.clienteId,
        notas:    body.notas,
      }
    })
    
    return NextResponse.json(reserva, { status: 201 })
  } catch (error) {
    return NextResponse.json(
      { error: 'Error al crear la reserva' },
      { status: 500 }
    )
  }
}

Cliente de Prisma — archivo lib/prisma.ts

typescriptsrc/lib/prisma.ts
import { PrismaClient } from '@prisma/client'

// Patrón singleton: evita crear múltiples conexiones en desarrollo

  globalForPrisma.prisma = prisma
}

Tailwind CSS y componentes

Tailwind CSS te permite diseñar directamente en el HTML usando clases de utilidad. En vez de escribir CSS separado, describís el estilo con clases como bg-blue-500, p-4, rounded-lg.

Ejemplo: formulario de reserva

tsxsrc/components/ReservaForm.tsx (simplificado)
"use client"   // este componente corre en el navegador (no en el servidor)

import { useForm } from 'react-hook-form'
import { motion } from 'framer-motion'

export function ReservaForm() {
  const { register, handleSubmit } = useForm()

  const onSubmit = async (data) => {
    await fetch('/api/reservas', {
      method: 'POST',
      body: JSON.stringify(data)
    })
  }

  return (
    <motion.div
      initial={{ opacity: 0, y: 20 }}
      animate={{ opacity: 1, y: 0 }}
      transition={{ duration: 0.4 }}
      className="bg-white rounded-2xl shadow-lg p-8 max-w-md"
    >
      <h2 className="text-2xl font-bold mb-6">Nueva Reserva</h2>
      
      <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
        <input
          type="date"
          {...register('fecha')}
          className="w-full border rounded-lg p-3 focus:ring-2 focus:ring-blue-500"
        />
        <input
          type="number"
          placeholder="Cantidad de personas"
          {...register('personas')}
          className="w-full border rounded-lg p-3"
        />
        <button
          type="submit"
          className="w-full bg-blue-600 text-white py-3 rounded-lg hover:bg-blue-700 transition"
        >
          Confirmar Reserva
        </button>
      </form>
    </motion.div>
  )
}
10 — Animaciones

Framer Motion — animaciones profesionales

Framer Motion hace que las interfaces se muevan de forma natural. En vez de escribir keyframes CSS complejos, describís el estado inicial y el estado final, y la librería calcula la animación.

Los tres props fundamentales

🎬
initial
El estado antes de que el componente aparezca. Ejemplo: opacity: 0, y: 20
✅
animate
El estado final al que llega el componente. Ejemplo: opacity: 1, y: 0
⏱️
transition
Cómo se hace la transición. duration, delay, ease, type: "spring"
tsxejemplos de animaciones
import { motion } from 'framer-motion'

// 1. Aparecer desde abajo (fade up) — el más usado
<motion.div
  initial={{ opacity: 0, y: 30 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.5 }}
>
  Contenido que aparece animado
</motion.div>

// 2. Efecto "spring" — rebote natural
<motion.button
  whileHover={{ scale: 1.05 }}
  whileTap={{ scale: 0.95 }}
  transition={{ type: "spring", stiffness: 400 }}
>
  Botón con rebote
</motion.button>

// 3. Lista con animación escalonada (stagger)
<motion.ul
  variants={{
    show: { transition: { staggerChildren: 0.1 } }
  }}
  initial="hidden"
  animate="show"
>
  {reservas.map(r => (
    <motion.li
      key={r.id}
      variants={{ hidden: { opacity: 0 }, show: { opacity: 1 } }}
    >
      {r.cliente.nombre}
    </motion.li>
  ))}
</motion.ul>

12 — Buenas prácticas

Código profesional: lo que diferencia

El código que funciona y el código profesional no son lo mismo. Estas prácticas son las que distinguen un proyecto mantenible de uno que nadie puede tocar después de seis meses.

Variables de entorno

bash.env (nunca lo subas a GitHub)
# URL de la base de datos
DATABASE_URL="file:./dev.db"

# En producción sería algo así:
# DATABASE_URL="postgresql://user:password@host:5432/reservas"

# Para autenticación (futuro)
NEXTAUTH_SECRET="una-clave-secreta-muy-larga"

Errores comunes a evitar

❌
Errores frecuentes de principiantes
1) Hardcodear contraseñas en el código: password: "admin123". Siempre en .env.
2) No validar los datos que llegan de la API. Siempre usá Zod para validar el body.
3) Crear un nuevo PrismaClient en cada request. Usá el patrón singleton de lib/prisma.ts.
4) Poner lógica de base de datos en el componente. Eso va en la API o en Server Components.
5) No manejar los errores en los try/catch de la API.
✨
Principios de Clean Architecture
Separación de responsabilidades: un componente hace una sola cosa. ReservaForm maneja el formulario; ReservaCard muestra la reserva.

Modularidad: cada módulo es independiente y reemplazable sin romper el resto.

Escalabilidad: el código nuevo no rompe el código viejo. Agregás, no modificás.
