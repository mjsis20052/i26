Documentación Técnica: Agri-Nexus

Arquitectura y flujo de procesamiento sobre base documental de 30 años.

INTA-I26 NEXUS · v1.0

1. Introducción y Contexto

El presente documento describe la arquitectura técnica de un sistema de inteligencia artificial diseñado para aprovechar la base documental del INTA acumulada durante las últimas tres décadas.

1.1. El Problema

El INTA cuenta con un volumen extraordinario de conocimiento técnico que permanece subutilizado por barreras de acceso. Un productor no tiene forma eficiente de consultar 30 años de ensayos en segundos.

1.2. La Solución

Un sistema de tipo RAG (Retrieval-Augmented Generation) que indexa semánticamente la documentación y responde en lenguaje natural con validación experta.

2. Arquitectura Técnica: Componentes Clave

2.1. Dataset Institucional

Base de Activos

Conjunto estructurado que alimenta el aprendizaje. Incluye pares pregunta-respuesta validados por el INTA.

Clave: Activo diferencial
2.2. Chunking

Segmentación

División de PDFs extensos en fragmentos óptimos para máxima precisión de recuperación.

Clave: Granularidad semántica
2.3. Embeddings

Vectores Semánticos

Transformación de texto en coordenadas numéricas de alta dimensión para capturar el significado.

Clave: Búsqueda por intención
2.4. RAG Architecture

Recuperación Aumentada

Núcleo de confiabilidad: el modelo responde citando fuentes verídicas INTA en tiempo real.

Clave: Cero alucinaciones
2.5. Fine-tuning

Ajuste Regional

Especialización del modelo base para dominar el lenguaje técnico del agro y el vocabulario local.

Clave: Especialización posterior
2.6. Ranking Semántico

Re-ranking Experto

Ordenamiento por relevancia geográfica, recencia y jerarquía de fuente institucional.

Clave: Calidad de contexto
2.7. Modelo Base

Motores Open-Source

Uso de modelos potentes como Mistral o LLaMA 3 desplegables en infraestructura propia.

Clave: Soberanía de datos
2.8. Human-In-The-Loop

Validación Humana

Supervisión experta INTA antes de que la respuesta sea pública en la plataforma.

Clave: Garantía institucional

6. Consideraciones de Infraestructura

Despliegue Local

Alta soberanía de datos y control total del hardware.

  • GPU NVIDIA (mín. 8GB VRAM)
  • 2TB SSD (Corpus + VectorDB)
  • Ubuntu Server 22.04 LTS

Nube Híbrida

Escalabilidad total con costos operativos variables.

  • Pinecone / Weaviate Cloud
  • Modelos vía API (Claude/OpenAI)
  • Storage S3 Institucional

7. Glosario Técnico de Referencia

Token

Unidad básica de texto (aprox. 0.75 palabras). 1000 palabras = ~1300 tokens.

Embedding

Representación numérica de texto que captura significado semántico.

Vector Database

Sistemas como ChromaDB o pgvector especializados en búsqueda por similitud.

LLM

Large Language Model. Motor capaz de generar, resumir y razonar sobre texto.

Cuantización

Compresión del modelo (ej: 4-bit) para correr en hardware institucional estándar.

Similitud Coseno

Métrica matemática que mide la cercanía de ideas en el espacio semántico.
