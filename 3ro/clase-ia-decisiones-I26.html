01 · El problema real

30 años de conocimiento
que no llega

El INTA acumula tres décadas de investigación científica agropecuaria. Ese conocimiento existe en informes, publicaciones y bases de datos internas. El problema: para llegar al productor, tiene que pasar por un extensionista, y la comunicación se pierde, se simplifica de más, o directamente no ocurre.

El problema no es falta de información — es falta de acceso

La información existe y está documentada. El problema es que el formato, el lenguaje y el canal no permiten que llegue en el momento en que se necesita para tomar una decisión real en el campo.

Un sistema de IA que funciona únicamente con la documentación interna del INTA. No inventa. No alucina datos de internet. Responde preguntas del productor o del extensionista basándose exclusivamente en 30 años de investigación real.

02 · Conceptos clave de IA

Lo que necesitan
entender primero

Antes de escribir una línea de código, hay que tener claro el vocabulario. Estos no son conceptos teóricos — son las piezas del sistema que van a armar.

🧠
LLM
Modelo de Lenguaje Grande. Entiende preguntas en lenguaje natural y genera respuestas. GPT-4, Claude, Llama son ejemplos. No sabe nada de tu empresa — a menos que le des el contexto.
📐
Embedding
Transformar texto en números (vectores). "Soja con sequía" y "cultivo en estrés hídrico" son frases distintas pero tienen vectores cercanos. Así la búsqueda entiende sinónimos.
🗄️
Vector DB
Base de datos que guarda y busca embeddings por similitud semántica, no por texto exacto. Chroma, Pinecone, pgvector. Es la memoria del sistema.
🔍
RAG
Retrieval-Augmented Generation. Buscar los fragmentos relevantes de tus documentos y pasarlos como contexto al LLM. El modelo responde solo con lo que vos le das.
✍️
Prompt
La instrucción que le das al modelo. No es magia — es ingeniería. Define el rol, el contexto, las restricciones y el formato. Prompt = código que habla.
✂️
Chunk
Fragmento de documento. Los PDFs del INTA se cortan en piezas de ~500 palabras con overlap. Cada chunk se embeddea por separado. El tamaño del chunk afecta directamente la calidad de las respuestas.

Cómo se conectan — el flujo completo

1. Ingesta · PDFs → chunks → embeddings → Vector DB
Una sola vez
2. Query · Pregunta del usuario → embedding de la pregunta
Por cada consulta
3. Retrieval · Chunks más similares en la Vector DB
Por cada consulta
4. Augment · Prompt: contexto + pregunta + restricciones
Por cada consulta
5. Generate · LLM responde SOLO con el contexto dado
Resultado
📌
La restricción más importante del sistema

En el prompt le decimos al modelo: "Si la respuesta no está en los documentos que te doy, respondé que no tenés información suficiente." Esto convierte un LLM genérico en un sistema confiable.

03 · RAG en profundidad

El patrón que
resuelve el problema

RAG no es un producto ni una librería — es un patrón de arquitectura. Como MVC o REST. Podés implementarlo con distintas herramientas. Lo que no cambia es la lógica.

Por qué no alcanza con pasarle todos los documentos al LLM

El problema del contexto

Los LLMs tienen un límite de tokens. 30 años de informes del INTA son millones de palabras — no entran. RAG resuelve esto buscando solo los fragmentos relevantes para cada pregunta.

El problema del costo

Cada token que mandás al modelo tiene un costo. Mandar documentos completos cuando solo necesitás un párrafo es ineficiente. RAG manda solo lo necesario.

Comparando enfoques

Enfoque Cómo funciona Problema ¿Para INTA?
LLM solo Responde con lo aprendido en entrenamiento No sabe nada del INTA. Puede inventar. No sirve
Fine-tuning Reentrenar el modelo con docs del INTA Caro, lento, difícil de actualizar. Excesivo
Búsqueda clásica Buscar por palabras clave en documentos No entiende sinónimos. Devuelve docs, no respuestas. Parcial
RAG Busca semánticamente + LLM con contexto Requiere infraestructura inicial. Bien implementado: alucinación casi nula. Ideal ✓

El prompt del sistema — la pieza más importante

System prompt · INTA Decision Engine
Sos un asistente técnico del INTA (Instituto Nacional de Tecnología Agropecuaria). Tu única fuente de información son los documentos de investigación que se te proveen como contexto.

Reglas estrictas:
1. Solo respondés basándote en el CONTEXTO que recibís. Nunca en conocimiento general.
2. Si la respuesta no está en el contexto, decís: "No tengo información en los documentos del INTA para responder esta pregunta."
3. Siempre citás el documento o sección de donde proviene la información.
4. Hablás en lenguaje claro, sin jerga técnica, a menos que el usuario sea un investigador.
Este prompt es el que diferencia el sistema de una búsqueda de Google o de un chatbot genérico. Las reglas son las que garantizan confiabilidad.

Opción simple (para empezar)

  • LLM: API Anthropic Claude o OpenAI GPT
  • Embeddings: OpenAI text-embedding-3-small
  • Vector DB: ChromaDB (local, sin infraestructura)
  • Backend: Node.js + Express
  • Frontend: React + fetch

Opción producción (privacidad total)

  • LLM: Modelo local con Ollama
  • Embeddings: nomic-embed-text (local)
  • Vector DB: pgvector en PostgreSQL
  • Orquestación: LangChain o LlamaIndex
  • Deploy: Docker + servidor INTA
🔒
Privacidad de los datos

Con Ollama podés correr un LLM completamente local. Los documentos del INTA nunca salen del servidor. Para una institución pública con investigación sensible, esta es la opción correcta a mediano plazo.

05 · Código base funcionando

Del concepto
al código real

1. Ingesta — dividir documentos en chunks

ingesta/load_docs.py python 
import os
from langchain.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

def cargar_documentos(ruta_docs="./docs"):
    documentos = []
    for archivo in os.listdir(ruta_docs):
        if archivo.endswith(".pdf"):
            loader = PyPDFLoader(f"{ruta_docs}/{archivo}")
            documentos.extend(loader.load())
    return documentos

def dividir_en_chunks(documentos):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=500,    # palabras por chunk
        chunk_overlap=50,  # overlap para no perder contexto en cortes
    )
    return splitter.split_documents(documentos)

if __name__ == "__main__":
    docs   = cargar_documentos()
    chunks = dividir_en_chunks(docs)
    print(f"Documentos: {len(docs)} · Chunks: {len(chunks)}")

2. Embeddings — transformar texto en vectores

ingesta/embed_chunks.py python 
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from load_docs import cargar_documentos, dividir_en_chunks

def indexar_documentos():
    docs   = cargar_documentos()
    chunks = dividir_en_chunks(docs)

    embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

    # Chroma guarda los vectores localmente
    vectorstore = Chroma.from_documents(
        documents=chunks,
        embedding=embeddings,
        persist_directory="./database/vector_store"
    )
    vectorstore.persist()
    print("✓ Base de vectores lista.")

indexar_documentos()

3. API — el endpoint de consulta

api/routes/query.js javascript · express 
const express = require('express');
const router  = express.Router();
const { buscarContexto } = require('../services/retriever');
const { consultarLLM }   = require('../services/llm');

// POST /api/consulta · Body: { pregunta: "..." }
router.post('/', async (req, res) => {
  const { pregunta } = req.body;
  if (!pregunta) return res.status(400).json({ error: 'Pregunta requerida' });

  const contexto  = await buscarContexto(pregunta, topK=5);
  const respuesta = await consultarLLM(pregunta, contexto);

  res.json({
    respuesta,
    fuentes:       contexto.map(c => c.metadata.source),
    chunks_usados: contexto.length
  });
});

module.exports = router;

4. Servicio LLM — donde vive el system prompt

api/services/llm.js javascript · anthropic sdk 
const Anthropic = require('@anthropic-ai/sdk');
const client    = new Anthropic();

const SYSTEM_PROMPT = `
Sos un asistente técnico del INTA.
Tu única fuente de información son los fragmentos que se te proveen.

REGLAS:
1. Solo respondés con información del CONTEXTO provisto.
2. Si no encontrás la respuesta, decís exactamente:
   "No tengo información en los documentos del INTA para esta consulta."
3. Citás siempre el nombre del documento de origen.
4. Usás lenguaje claro y directo.
`;

async function consultarLLM(pregunta, fragmentos) {
  const contextoTexto = fragmentos
    .map((f, i) => `[Fragmento ${i+1} · ${f.metadata.source}]\n${f.pageContent}`)
    .join('\n\n---\n\n');

  const response = await client.messages.create({
    model:   'claude-sonnet-4-20250514',
    max_tokens: 1024,
    system:  SYSTEM_PROMPT,
    messages: [{ role: 'user', content: `CONTEXTO:\n${contextoTexto}\n\nPREGUNTA:\n${pregunta}` }]
  });

  return response.content[0].text;
}

module.exports = { consultarLLM };

5. Frontend — la interfaz del extensionista

frontend/src/components/ChatBox.jsx jsx · react 
import { useState } from 'react';

export default function ChatBox() {
  const [pregunta,  setPregunta]  = useState('');
  const [respuesta, setRespuesta] = useState(null);
  const [fuentes,   setFuentes]   = useState([]);
  const [cargando,  setCargando]  = useState(false);

  const consultar = async () => {
    if (!pregunta.trim()) return;
    setCargando(true);

    const res  = await fetch('/api/consulta', {
      method:  'POST',
      headers: { 'Content-Type': 'application/json' },
      body:    JSON.stringify({ pregunta })
    });
    const data = await res.json();

    setRespuesta(data.respuesta);
    setFuentes(data.fuentes || []);
    setCargando(false);
  };

  return (
    <div>
      <h1>Consultor INTA</h1>
      <textarea value={pregunta} onChange={e => setPregunta(e.target.value)}
        placeholder="¿Cómo manejar soja en condiciones de sequía?" />
      <button onClick={consultar}>{cargando ? 'Consultando...' : 'Consultar'}</button>
      {respuesta && (
        <div>
          <p>{respuesta}</p>
          <ul>{fuentes.map((f,i) => <li key={i}>{f}</li>)}</ul>
        </div>
      )}
    </div>
  );
}

El circuito completo en una oración

Pregunta → React hace POST → Express busca 5 chunks similares en Chroma → arma prompt con esos chunks → Claude responde solo con esa información → React muestra respuesta con fuentes.

06 · Herramientas del ecosistema

El stack que
necesitan conocer

LangChain

El framework más usado para RAG. Tiene abstracciones para loaders, splitters, embeddings, vector stores y chains. Python y JS.

Recomendado para empezar

LlamaIndex

Especializado en RAG. Más opinado que LangChain — menos configuración. Ideal cuando el caso de uso es principalmente "preguntas sobre documentos".

Alternativa sólida

Correr modelos completamente local

Ollama — setup inicial bash 
# Instalar Ollama
curl -fsSL https://ollama.ai/install.sh | sh

# Descargar modelo LLM (llama3 es liviano y capaz)
ollama pull llama3

# Descargar modelo de embeddings (sin internet, sin API key)
ollama pull nomic-embed-text

# Levantar el servidor (escucha en localhost:11434)
ollama serve

Para prototipar sin código

AnythingLLM

App de escritorio que implementa RAG con interfaz visual. Subís los PDFs del INTA, configurás el modelo y tenés un RAG funcionando en minutos. Perfecto para validar el caso de uso antes de codear.

Open WebUI

Interfaz web para Ollama. Permite probar modelos locales con una UI tipo ChatGPT. Útil para mostrarle al ingeniero del INTA cómo se vería el sistema antes de construirlo.

⚠️
La trampa de las herramientas

LangChain, LlamaIndex, Ollama son herramientas — no soluciones. El valor está en entender el patrón RAG. Si entienden el flujo, pueden implementarlo con cualquier stack.

07 · Actividad práctica

Diseñen el sistema
para su contexto

El patrón RAG aplica a cualquier organización con conocimiento acumulado. Elijan un caso real — de Dolores, de la región, de algo que conozcan — y diseñen el sistema.

Actividad 01 · Individual · 10 minutos
Identificar el problema

Sin hablar con el equipo, respondé en papel:

  • ¿Qué organización conocés que tenga conocimiento acumulado que no llega a quien lo necesita?
  • ¿Quién haría la consulta? ¿Con qué urgencia?
  • ¿Qué tipo de documentos existentes podrían ser la fuente?
  • ¿Qué pasaría si el sistema respondiera algo incorrecto? (pensar el riesgo)
Actividad 02 · Equipo · 20 minutos
Diseñar el sistema

Completen este esquema para su caso:

  • Usuario: ¿quién hace la consulta?
  • Problema: ¿qué no puede resolver hoy sin el sistema?
  • Fuente de documentos: ¿qué documentación existe y en qué formato?
  • Consulta ejemplo: 3 preguntas reales que haría el usuario
  • Restricción del sistema: ¿qué NO debe responder aunque le pregunten?
  • Riesgo principal: ¿qué puede salir mal y cómo lo mitigás?
Actividad 03 · Equipo · 10 minutos
Escriban el system prompt

El prompt que usarían para su sistema. Tiene que incluir:

  • El rol del asistente (quién es)
  • La fuente de información (de dónde viene el conocimiento)
  • Las reglas claras (qué hace si no tiene la respuesta)
  • El tono (¿técnico? ¿simple? ¿para quién?)

Un buen prompt de 4 líneas vale más que 100 líneas de feature.

📌
Criterio de éxito de esta actividad

No es que tengan el código. Es que puedan explicar el sistema en 3 minutos a alguien que no sabe nada de IA: cuál es el problema, quién lo usa, de dónde viene la información y por qué el sistema no va a inventar respuestas.
